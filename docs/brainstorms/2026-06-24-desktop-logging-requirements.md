# 스펙: 데스크톱 앱 프로그램 로깅 + 개발자 모드

> 작성일 2026-06-24 · 유형: 기능 스펙(요구사항). 구현 방식은 별도 단계에서 정한다.

## 1. 개요

agentsafe 데스크톱 앱(Wails)에 **자체 프로그램 로깅 체계**와 **개발자 모드**를 추가한다. 앱이 자기 자신의 로직을 항상 파일에 기록하고, 필요 시 상세도를 높이며, 기존 Log Console에서 task와 앱 내부 로그를 함께 보고, 영구 로그 파일을 앱에서 열 수 있게 한다.

## 2. 배경 / 문제

현재 가시성 구조의 두 구멍:

1. **앱 자신의 로직에는 로그가 없다.** `internal/output` sink는 *task*(prepare/diff/sync/pull)의 CLI 텍스트만 Log Console로 흘린다. `apps/desktop/app.go`의 `startup()`, 워크스페이스 복원, 터미널 생명주기, 이벤트 발행, 삼켜진 `_ = ...` 에러는 아무 흔적도 남기지 않는다. Go 코드에 구조적 로깅이 전무하다.
2. **기록이 휘발성이다.** 기존 Log Console(`apps/desktop/frontend/src/components/ui/log-console.tsx`)은 메모리 전용(최대 200개)이라 재시작 시 사라지고 파일로 남지 않는다.

동기: **(a)** 조용히 실패하는 앱 내부 로직을 사후에 디버깅(실패 후 모드를 켜는 건 늦으므로 baseline은 항상 ON이어야 함), **(b)** 타인이 버그 보고 시 첨부/전송할 로그 파일(→ 민감정보가 새면 안 됨).

## 3. 목표 / 비목표

**목표**
- 앱 내부 로직을 항상 파일에 기록(baseline)하여 조용한 실패를 사후에 추적 가능.
- 타인에게 전달 가능한 안전한 로그 파일 제공.
- 기존 Log Console에서 task + 앱 내부 로그를 라이브로 함께 확인.

**비목표**
- 앱 내 완전한 파일 뷰어(검색/레벨 필터/세션 탐색).
- 로그의 경로에서 홈/유저명 마스킹.
- 기존 mask 엔진(`internal/agent/security.go`)을 로그 라인에 적용.
- CLI의 파일 로깅 채택(`--log-file`).

## 4. 기능 요구사항

**F1 — 항상 ON baseline 파일 로깅**
- 앱은 시작 시점부터(워크스페이스가 열리기 전 포함) 자기 로직의 주요 이벤트와 에러를 파일에 기록한다.
- 기본 레벨은 info. 에러는 항상 기록된다.

**F2 — 개발자 모드 (상세도 + 뷰어 진입점)**
- 개발자 모드는 별도의 로깅 on/off 스위치가 아니다. 켜면 로그 상세도를 **debug**로 올리고, 뷰어의 로그 파일 접근 수단을 노출한다.
- 설정 화면(`apps/desktop/frontend/src/pages/SettingsPage.tsx`)에서 토글한다. 앱 레벨 설정으로 저장되어 재시작 후에도 유지된다(기존 `agentsafe.terminalProgram` / 테마 저장 방식과 동일).
- 토글 변경은 즉시 반영된다(앱 재시작 불필요).

**F3 — 뷰어: 기존 Log Console 확장**
- 신규 화면을 만들지 않고 기존 Log Console을 확장한다.
- task 출력에 더해 **앱 내부 로그(startup·워크스페이스·터미널·이벤트·에러)** 를 라이브로 함께 표시한다.

**F4 — 영구 로그 파일 접근**
- Log Console에서 "**로그 파일 열기**"와 "**폴더 열기**" 동작을 제공한다(과거 세션·전체 로그는 외부 에디터로 확인).
- 로그 파일은 워크스페이스가 아니라 **앱 레벨 단일 위치**에 둔다(`os.UserConfigDir()` 하위의 agentsafe 로그 폴더). 근거: 워크스페이스 열기 전부터 기록되어야 하고, 타인이 찾아 보내기 쉬워야 한다.

**F5 — 보안: 안전한 필드만 기록**
- 로그에는 **작업명, repo/feature 이름, 경로, 소요시간, 에러 메시지**만 남긴다.
- **secret 값·토큰·자격증명·파일 내용은 절대 기록하지 않는다**(설계상 차단). 자격증명은 이미 메모리 전용이다.
- 경로는 그대로 기록한다(디버깅에 유용, secret 아님).

## 5. 동작 상세

- **레벨**: info(기본) / debug(개발자 모드). 에러는 레벨과 무관하게 기록.
- **기록 대상(예)**: 앱 시작/워크스페이스 복원·전환, 터미널 open/타임아웃/close, `agent:exit`, 각 task의 시작·종료·에러(라벨·소요시간), 현재 삼켜지는 `_ = ...` 에러들.
- **파일 보관**: 무한히 커지지 않도록 크기 상한 + 단순 회전(상한·세대 수는 구현 시 확정).
- **라이브 표시**: 백엔드가 새 로그 이벤트를 프론트로 보내고, Log Console이 이를 "앱 로그" 스트림으로 누적(기존 `task:*` 이벤트와 동형).

## 6. 영향 받는 영역 (참고)

- 백엔드: `apps/desktop/app.go`(계측·로그 이벤트 발행·로그 파일 열기), `apps/desktop/main.go`(초기화), 공유 로깅 로직.
- 프론트: `apps/desktop/frontend/src/components/ui/log-console.tsx`(앱 로그 구독 + 파일 버튼), `apps/desktop/frontend/src/pages/SettingsPage.tsx`(개발자 모드), `apps/desktop/frontend/src/i18n/translations.ts`(문자열).
- CLI/GUI 패리티: 항상 ON 파일 로깅·뷰어·개발자 모드는 **데스크톱 전용**(CLI는 이미 터미널 출력). AGENTS.md 패리티 규칙의 의도적 예외로 문서화.

## 7. 성공 기준

1. 개발자 모드 OFF에서 실패하는 작업을 유발하면, Log Console "앱 로그"에 에러가 라이브로 보이고 동일 내용이 파일에도 남는다.
2. 개발자 모드 ON으로 바꾸면(재시작 없이) 이후 로그에 debug 상세가 추가된다.
3. "폴더 열기"로 앱 레벨 로그 폴더가 열린다.
4. 앱을 재시작해도 직전 세션 로그가 파일에 보존되어 있다.
5. 자격증명·토큰을 사용하는 경로를 거친 뒤 로그 파일에 secret 값이 존재하지 않는다.

## 8. 열린 질문 / 가정

- 로그 파일 위치 = `os.UserConfigDir()/agentsafe/logs/` (가정). 워크스페이스별 로그가 낫다면 변경 가능.
- 회전 상한(예: ~5MB)·세대 수·파일 포맷(JSON line 권장)은 구현 단계에서 확정.
- 개발자 모드가 debug 레벨 외에 추가로 노출할 UI(예: 디버그 필터)는 최소로 두되 구현 시 조정.
